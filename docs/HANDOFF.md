## 2. What the owner wants (in their words, condensed)

- The game must look **made by a studio, not generated by AI**. Their test: "if someone showed you this picture,
  is this a real game, or did someone make it with AI?"
- They **like the original olive-green painted-steel look** (the locker door, the panels) because it is
  **textured and looks like part of the game**. Keep it; finish it.
- They **rejected**: brass/gold everywhere, orange ("looks like a sports nutrition app"), the green phosphor/CRT
  UI, the paper "scrapbook/logbook" look, flat CSS gradients, and anything that feels like a web app laid over
  the game.
- They want **more texture and detail**, **designed PNG assets rather than CSS gradients**, things **centred and
  not overlapping**, **readable**, **cohesive**, nothing confusing.
- They want me to **flag game-mechanic problems**, and they warned: **do not call something too hard because a bot
  struggled**. Humans react better than our test bots (they rejected lengthening the trawl tow for this reason).
- The X key (dev cheat that gives max sub and cash) **must stay easy to reach**; it is removed before release.
- Mobile is **out of scope** for now.
- Work on a branch, push, **never merge**. Version bump on every change (see section 6).

## 4. The rules (short form of `docs/ART_DIRECTION.md`)

1. One material: painted olive steel. Paper only where the object is paper (journal, catalog screen).
2. One "press me": cream plate, dark words. Everything else olive plate, cream words. Chosen = cream ring.
3. Two faces: **EB Garamond** for words; **IBM Plex Mono** only for numbers (cash, depth, prices, counts).
4. Names painted on the steel, not on stuck-on plates. Labels in Garamond small caps.
5. No captions unless a player would otherwise be lost. No " · " strings in chrome. No unicode as icons.
6. Same thing, same look (one close, one cash, one row, one tab).
7. No brass, no gold, no orange accent, no CSS gradients for surfaces; paint it in `olive_kit.py` instead.

## 6. How to work in this repo

- Serve: `python3 -m http.server 8765` (background, long timeout) from the repo root.
- **After every version bump** (`js/version.js`, and the version line in `README.md`): run
  `python3 tools/stamp.py`. It stamps every module and both stylesheets in `index.html` so browsers do not mix
  cached old files with new ones.
- **Check modules strictly** before testing (twice this session a trailing `//` comment swallowed the code after
  it on the same line and the game failed to load; `node --check` did not catch it):
  `for f in js/*.js; do node --input-type=module --check < $f >/dev/null 2>&1 || echo BAD $f; done`
- Never put a `// comment` in the middle of a one-line statement; put comments on their own line.
- Test hook: `window.__earl` (`g`, `profile`, `ui`, `startRun`, `step(dt)`, `keys`, `pressed`, `hud`,
  `SPECIES_BY_ID`). `g.noDeath = 1` stops deaths.
- Playwright and Chromium are preinstalled; run scripts with `NODE_PATH=$(npm root -g) node script.cjs`.
  The previous session's harness scripts lived in a scratchpad that will not survive; rebuild what you need:
  a screenshot tour (open each panel via `window.__earl.ui.toggleX(true)` / `openShop('sub', ['sub'])`, press
  `k` for the chart, `Escape` for pause), a random-input soak, and the tutorial's first dive.
- CSS specificity trap: `:is()` takes the weight of its heaviest item. Rules in `css/olive.css` that list
  `#pause #resume` inside `:is()` carry two ids; to beat them you need equal weight (see the
  `:not(#_a):not(#_b)` trick used for disabled prices).
- Bash heredocs were blocked by a safety hook in this environment at times; write scripts with the file tool.
- Commits end with the attribution lines the environment provides; never put model names in the repo.
